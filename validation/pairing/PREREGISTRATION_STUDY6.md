# Preregistration, Study 6: finite windows and a second implementation (ns-3's own reorder buffer)

Status: written and hashed BEFORE any Study 6 confirmatory run. Date: 2026-10-18. Software-only (no hardware, no human annotation, no model judge).

## 0. Why this study exists and what is already known
- Study 5 (committed) proved and tested the airport structure for an IDEAL resequencer on the project's Python simulator and two synthetic generators. Two gaps were ours to close, not inherent: (i) no forced window advances, (ii) no second implementation of the reorder buffer.
- Smoke checks (seeds not used below): (a) one scripted three-flow ns-3 run (condition A2, 5 s, seed 1): 11,905 per-packet records, release law error 0.0 ms over 11,621 packets after a 200 ms warm-up, 3,104 blocked packets, no forced advances; the per-packet trace reproduces the binary's own cross_wait_ms (0.0821870) and within_wait_ms (0.0026203) to the printed precision. (b) 60 synthetic traces (generator seeds 1-20 for each of W = 8, 16, 64, 5% permanent loss) run through the unmodified BlockAckReceiver: the window-aware release law (T8 below) had error 0 and zero delivered-set mismatches, with forced advances in every trace.
- (c) Smoke of the timeout extension: a reference timer receiver (subclass of BlockAckReceiver implemented in study6.py; the project receiver has no timer) with window W in {8, 64}, hold timer tau in {none, 2, 5, 15} ms and permanent loss 0.05 or 0, 20 traces each (generator seeds 1-20): release-law error 0 and zero delivered-set mismatches over about 85,000 packets, forced events in most traces. (d) All runner tasks smoke-tested on seeds 1-3 (not confirmatory): ns-3 scripted run (condition A2, scale 2.5) release law error 0.0 over 29,024 packets, Python-receiver equivalence error 0.0, run-level cross/within columns reproduced to the printed precision, trace-derived maximum buffer occupancy equal to ns-3's buf_occ_max (25 = 25).
- Origin of the timeout/certificate additions: an adversarial review supplied by the user (not evidence) argued that an ideal-resequencer theory is not a theory of the deployed receiver; this amendment (written before hashing) therefore adds a hold timer, a bounded-error comparison between ideal and forced-release blame, and a trace-level applicability certificate with a soundness check.
- Not known: everything in the hypotheses below on the confirmatory seeds.
- The ns-3 binary is the frozen Mission 1 build (patched ns-3.47 with the recipient reorder-buffer observer); it is run unchanged with its existing --script and --traceOut options. No frozen file is modified.

## 1. Analytic statements (proved in the paper; tested below)
Notation as in Study 5: SN order index k, flow f(k), physical arrival A_k (A = infinity for a packet that never arrives).
- T8 (window- and timer-aware release law). Receiver with window W (forced advance when an SN >= window start + W arrives; in 802.11 the reorder-buffer capacity equals the window size, so W is the buffer capacity B) and hold timer tau (a buffered packet held for tau is released at its arrival time + tau, skipping all missing slots below it). Define F_j = min{A_s : s >= j + W}, T_j = min{A_s : s > j} + tau (T_j = infinity if tau = infinity) and the effective arrival of slot j as At_j = min(A_j, F_j, T_j) (A = infinity for a packet that never arrives). Then every released packet k has release time R_k = max_{j <= k} At_j, and the delivered set is {k : A_k < min(F_k, T_k) and R_k < infinity}.
- T9 (airport structure on effective arrivals). With b~_k = max over own-flow slots j <= k of At_j, lateness l~_{j,k} = (max over flow-j slots l < k of At_l minus b~_k)^+ and X~_k = R_k - b~_k, we have X~_k = max_{j != f(k)} l~_{j,k}. Theorems T3-T5 of Study 5 (closed-form Shapley blame, masking, stability) hold unchanged for l~; the blame of a skipped slot goes to the flow that owns the slot (information available at the sender, not at the receiver).
- T10 (bounded error between ideal and forced-release blame; loss-free traces). Let delta_k = max_{j <= k} (A_j - At_j). Then |l~_{j,k} - l_{j,k}| <= delta_k for every j, hence ||phi(l~) - phi(l)||_1 <= 2 m delta_k (m = number of other flows), and l~ = l (identical blame) whenever delta_k = 0, i.e. no slot up to k was released early.
- T11 (applicability certificate). Call packet k certified if its release time equals the maximum arrival time over received packets with SN <= k. If no slot up to k was resolved before its physical arrival (At_j = A_j for all j <= k), k is certified (soundness: a rejection implies that a forced release or loss occurred before k).
- T1 (ideal release law, Study 5) is the case W = infinity.

## 2. Hypotheses, data, thresholds
Errors are maximum absolute differences. Seeds are fresh. Intervals (descriptive) are percentile bootstraps over runs (10,000 resamples, default_rng(20261041)).

H20 (window- and timer-aware release law). Generator: 300 packets, sends Poisson with rate 1 per ms, 4 flows uniform, delay = Pareto(shape 1.5, scale 1 ms) + U(0, 2) ms, each packet lost permanently with probability ploss. Grid: W in {8, 16, 64} x tau in {none, 3, 10} ms x ploss in {0.05, 0} = 18 configurations, 50 traces each (configuration index c = 0..17 in the order W, tau, ploss; seeds 27000 + 100 c + i, i = 0..49), each passed through the receiver of study6.py (TimeoutReceiver; with tau = none it behaves exactly as the unmodified BlockAckReceiver). H20 is confirmed if for every released packet |rel_time - max_{j<=k} At_j| <= 1e-9, the delivered set equals the characterisation of T8 (zero mismatches) in every trace, and at least 90% of all 900 traces contain at least one forced event (window advance or timeout). Reported: events per configuration and the share of packets delivered.

H21 (airport structure on effective arrivals; bounded error; certificate soundness; same traces). (a) For every released packet: |X~_k - max_j l~_{j,k}| <= 1e-9; closed-form Shapley equals subset-enumeration Shapley on 100 random packets per trace and sums to X~_k (<= 1e-9); three random (victim, coalition) draws per trace: running the IDEAL resequencer (dense renumbering) on the effective arrival times of the slots of the victim and the coalition gives victim cross-blocking equal to max_{j in T} l~ (<= 1e-9); sum LOO <= X~ <= sum l~ and the LOO formula of Study 5 T4 hold (tolerance 1e-12); core membership on 20 random subsets per sampled packet (tolerance 1e-12). (b) On the loss-free configurations (ploss = 0), for every released packet |l~_{j,k} - l_{j,k}| <= delta_k and ||phi(l~) - phi(l)||_1 <= 2 m delta_k (tolerance 1e-12), where l is computed from physical arrival times (T10). (c) Certificate soundness (T11): over all traces, no packet is rejected (release time differs from the received-arrival prefix maximum by more than 1e-9) unless some slot up to k was resolved before its physical arrival. Descriptive: share of blocked packets whose largest lateness comes from a skipped slot; certified share per configuration.

H22 (release law on ns-3's own reorder buffer). Scripted three-flow traffic in the frozen ns-3.47 binary, FIFO (scheduler 0), simTime 5 s, warmup 0, drain 0, conditions A1 and A2 (mcs, widths, rss from configs/conditions.json), load scale s in {1, 2.5}: flow 1 Poisson 400 packets/s of 200 B, flow 2 Poisson 1500 s packets/s of 1000 B, flow 3 Poisson 800 s packets/s of 600 B, send times restricted to (0.1, 4.5) s (script rng default_rng([seed, condition index, load index])); ns-3 seeds 61-100; 2 conditions x 2 loads x 40 seeds = 160 runs, 5 s each. Sequence numbers are unwrapped from the 12-bit value exactly as the binary does (insertion order, running maximum). Runs with forced_adv_events > 0 or a failed runtime audit are excluded and counted. For every released packet with insert time >= 200 ms (to exclude the untagged ARP frames at the start): |rx_release_ms - max over traced packets with unwrapped SN <= its own of rx_insert_ms| <= 1e-6 ms (trace resolution). H22 is confirmed if there is no violation.

H23 (cross-implementation equivalence and structure on ns-3 arrivals). On the same runs: (a) the unmodified BlockAckReceiver (unbounded window, dense SN by unwrapped order) fed with the ns-3 insert times reproduces every ns-3 release time (insert >= 200 ms) within 1e-6 ms; (b) the Study 5 oracles O2, O3, O4, O6, O7 (cross-blocking = max lateness; closed-form = enumerated Shapley; truncate-and-rebuild; LOO/sub-additivity; core) hold with the same tolerances on the ns-3 arrival times (O2 relative to the Python receiver's own cross-blocking). Descriptive: share of blocked packets with at least two late flows, by condition and load.

H24 (ns-3 instrumentation identity). For each H22 run, the means over flow-1 packets of the whole wait attributed to a cross-flow binding blocker (cross) and to an own-flow blocker (within), derived from the trace with the rule of the binary (blocker = last-inserted lower-SN MPDU after the packet's own insertion, ties by larger unwrapped SN), equal the run's own cross_wait_ms and within_wait_ms columns within 1e-6 ms absolute. H24 is confirmed if all runs agree.

D2 (definition gap, descriptive; no threshold). For the main-campaign configuration (two flows, the standard traffic of Mission 1, scheduler FIFO, simTime 10 s, warmup 0.5 s, drain 0.3 s, bulk rate = bulk_mbps[load] of the condition) in conditions A1 and A2 at loads L0, L1, L2, ns-3 seeds 101-110 (60 runs), compute over flow-1 packets with first transmission in [0.5 s, 9.7 s]: the mean pure cross-blocking X (R - b), the mean self-blocking S, and the mean ns-3-style cross wait (whole wait when the binding blocker is another flow). Report per cell the ratio mean X / mean ns-3-style cross wait. Purpose: quantify how the cross_wait_ms used as "X" in Studies 3 and 4 differs from the pure X of the theory.

Validity: V17 runtime audit passes in all included runs (audit_sn_changed = audit_intra_flow_inv = audit_sn_dup = 0, audit_untagged_tx <= 20); V18 unwrapped sequence numbers are unique within every run; V19 the number of packets excluded as warm-up is reported.

## 4. Claims NOT made
No claim for ns-3's BAR-triggered forced releases (the mechanism by which the originator moves the recipient window after a drop), for timeouts, or for hardware; the ns-3 scenarios use fixed Poisson traffic over two links and one STA, not the main-campaign traffic (except D2); the window law is tested on the project's BlockAckReceiver and the timer law on a reference timer receiver we implement (the project receiver has no timer); ns-3's forced releases did not occur in any run and are not tested; attribution of a skipped slot to its owner needs sender-side information.
